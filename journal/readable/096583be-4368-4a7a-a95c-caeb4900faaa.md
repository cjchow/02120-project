## What you learned today

**Food-web modeling**
- Your model is **bottom-up**: prey only decline from lack of food, never from being eaten. Doubling predators doesn't change herbivores at all.
- Adding top-down effects would need an eating rate that neither paper gives you. So you kept the model as is and wrote it up as an **assumed limitation**.
- **Reaction-diffusion** needs space for things to spread across. Your global-mean model has no space, so only the "reaction" half could ever fit.

**Python**
- `web[i+1]` from `web[i]` is a **recurrence relation**. A loop (**iteration**) is the right tool here because Python stops recursion at about 1,000 levels deep (side quest pinned for later).
- Inputs with default values (`floor=1e-4`) must come **last** in a `def`.
- A function can't see another function's variables, so pass values in as inputs.
- Once you hand in a single row, `web[i, 0]` becomes `row[0]`: one index instead of two.
- Order of operations: `(food - row) * dt` and `food - row * dt` are very different numbers (−0.007 vs 0.191).

**Refactoring and testing**
- **Refactoring** means moving code into its own function without changing what it does. You confirmed it with a **regression check**: identical output before and after.
- A test checks that the code does the math you *meant*. It doesn't check that the model is realistic.
- Write the expected value as the **exact hand formula**, not a rounded number.
- **Tolerance** is the largest difference you'll accept. It must sit *between* "correct" (about 0) and "buggy" (for the floor case, 3.3e-10).
- A test that's never called, or that can't fail, proves nothing. **Mutation testing** (breaking the code on purpose) shows that a test really works.
